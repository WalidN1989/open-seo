SEO Report turns finished research into an HTML document saved in the project's Research reports page. Ask for a report after an audit, keyword research, competitor analysis or local visibility review.

## What you get

- A report link, a short verdict and the leading recommendation in chat.
- A document your workspace can read on a phone or print to PDF.
- A summary agents can read before repeating the same research.

Saving and reading a report uses no credits. Research that supplies its evidence can still use paid data tools.

## Reuse a report brief

A template stores instructions about audience, sections, tone and sign-off. Ask the agent to create one when you want to reuse that brief, then name it when requesting a report. A template does not change the report viewer's security restrictions.

## Replacing and retaining reports

For a revision covering the same subject and period, the agent reuses the saved report's id. Replacement overwrites the document: there is no version history or undo. A different subject or reporting period gets a new report.

Saved reports remain until a person deletes them in the app. The separate research log retains its newest entries within a 90-day window; pruning that log does not delete reports.

## Private and public links

New reports are private to the workspace. A request to save a report does not publish it. Public sharing is a separate action that you must explicitly request.

Anyone holding a public link can read the latest saved version without an account. Revoking sharing disables that link; enabling it again creates a new link. Account-based Digital Urgency deployments support sharing. Cloudflare Access and local no-auth deployments do not.

## Viewer limits

Reports use inline CSS, tables and static SVG charts. Their own scripts, external images, fonts and network requests are blocked. Print or export opens the browser's print dialog, where you can choose Save as PDF. Report map widgets and social preview images are not part of this integration.
